## Name projects with intent

Project names should help people answer two questions instantly:

- what work is being tracked
- who the work is for

Examples:

- `Q2 Product Launch`
- `ACME Website Refresh`
- `Internal Ops Improvements`

## Use members deliberately

Project membership should reflect actual responsibility. Add reviewers and stakeholders only when they need visibility or action rights.

### Recommended ownership model

Assign one clear owner for each project. That person should keep the workflow and priorities clean.

## Keep the description operational

Project descriptions are not marketing copy. They should explain scope, outcomes, and decision boundaries.

## Archive instead of deleting

If a project is complete, archive it unless you are certain the history is no longer needed.
