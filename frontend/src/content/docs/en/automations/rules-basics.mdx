## Start with one painful repetition

Automations are most useful when they remove a task update people repeatedly forget to perform.

## Good first automation examples

- set priority when a task reaches a critical review column
- auto-assign a reviewer for specific work types
- move tasks after a predictable trigger

### Keep actions understandable

If someone cannot explain what a rule does in one sentence, it is too complex for the first version.

<WarningCallout title="Avoid rule chains">
Stacking multiple automations on top of each other makes failures and notifications harder to reason about.
</WarningCallout>
