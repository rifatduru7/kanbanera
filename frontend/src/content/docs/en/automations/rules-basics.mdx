## What automation rules are for

Automation rules handle narrow, repeatable workflow decisions inside a project. They are best for actions that always follow the same event.

## Supported trigger patterns

The current product exposes rule triggers such as:

- task moved to a column
- task created
- task assigned

## Supported action patterns

Available actions include:

- set priority
- set assignee
- add label
- move to another column
- archive task

## Good first rules

Start with one of these:

- when a task enters Review, assign a reviewer
- when a task is created, add a default label
- when a task reaches Done, archive it or move it to the final column

## What not to automate first

Avoid rules that:

- make critical decisions without team trust
- change multiple fields unexpectedly
- hide workflow problems instead of exposing them

<WarningCallout title="Keep rules observable">
If the team cannot predict what a rule will do, the rule is too opaque. Start simple and review outcomes frequently.
</WarningCallout>

## Rules vs Flows

Use automation rules when a single trigger should produce a single operational response.

Use Flows when the logic needs a visual chain with triggers, branching, and multiple connected steps.
