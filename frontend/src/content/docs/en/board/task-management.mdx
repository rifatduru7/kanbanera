## Create tasks with usable context

A good task title is specific enough to stand on its own. Descriptions should capture acceptance criteria, not a long status report.

## Use assignees and due dates together

Assignees create accountability. Due dates create planning pressure. One without the other is usually incomplete.

### Subtasks for execution detail

Subtasks are best when a larger task has multiple concrete checkpoints owned by the same person or team.

## Comments should move work forward

Use comments for decisions, blockers, and review notes. Avoid duplicating information already visible in the task fields.

<SuccessCallout title="Healthy board habit">
If a task changes state, update the task fields immediately so the board and notifications stay trustworthy.
</SuccessCallout>
