## What belongs in the task modal

The task modal is where card-level work becomes executable and reviewable. It supports:

- title and description
- status and priority
- assignee and due date
- tags
- subtasks
- attachments
- comments and activity

## Descriptions should remove ambiguity

A task description should answer:

- what needs to be done
- what “done” means
- what context the assignee needs

If the task requires review, include the expected reviewer perspective in the description or subtasks.

## Subtasks vs comments

Use subtasks for actionable work items that contribute to completion.

Use comments for discussion, clarification, and status context.

If a recurring comment turns into action, convert that idea into a subtask or a separate task.

## Attachments and working material

Attachments are useful when the task depends on deliverables, screenshots, exports, drafts, or review assets. Keep filenames understandable so reviewers can tell what changed.

## Tags and lightweight structure

Tags work best when they help grouping or search. They are not a replacement for status or priority.

Use tags for:

- domain labels
- team labels
- release or stream labels

## Activity and audit trail

The activity area helps you reconstruct what changed and when. This matters most when multiple people touch the same task over time.

## Time tracking entry point

If your workflow uses time tracking, start work from the task context so logged time stays tied to the correct task.
