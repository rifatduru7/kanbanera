## Create your first project

Open **Projects** and create a new workspace for a team, client, or initiative. Keep the project name explicit and avoid generic labels.

### Add a focused description

A short description helps people understand the purpose of the board without opening extra context.

## Invite the right members

Only add the people who will actively plan, execute, or review work. You can adjust roles later.

## Define a minimal workflow

Start simple. A good first structure is:

- Backlog
- In Progress
- Review
- Done

<WarningCallout title="Do not over-model too early">
If your team is still learning the product, too many columns and rules will slow adoption.
</WarningCallout>

## Add real tasks

Use real work instead of placeholder tasks. Add assignees, priority, due dates, and subtasks where needed.

## Validate the timeline

After tasks exist, open the Gantt page to confirm whether your due dates are realistic.
