<Callout title="Goal">
By the end of this guide, you will have a live project with columns, tasks, assignees, and a usable planning baseline.
</Callout>

## Before you begin

You need:

- a signed-in workspace account
- permission to create projects
- at least one real teammate or test member to invite

## Step 1: Create a project

Open **Projects** and create a new project with a clear name, short description, and a color that helps your team recognize it quickly.

Use a real project name if possible. Documentation is more useful when it reflects the workflow you already run.

## Step 2: Confirm the column structure

Open the project in **Board** and review the columns. Keep them close to reality. For most teams, a small number of statuses works better than a large process map.

Good first examples:

- Backlog
- Ready
- In Progress
- Review
- Done

## Step 3: Create your first tasks

Add a few real tasks instead of placeholders. Include:

- a clear title
- assignee when known
- due date if delivery timing matters
- priority only when it helps decision-making

## Step 4: Open task details

Use the task modal to add:

- description
- subtasks
- attachments
- comments
- tags

This is where a short card turns into actionable work.

## Step 5: Validate the schedule

Open **Calendar** for date distribution, then open **Gantt** if you need a broader timeline view. If a task has no due date, it will be less useful in planning views.

## Step 6: Add one automation

Create one simple automation rule after the manual process is already clear. Good first examples are:

- when a task moves to Done, archive it later
- when a task is assigned, add a specific label
- when a task enters Review, lower or raise priority intentionally

## Step 7: Invite the project team

Open **Members** or project settings and invite the people who should work in that project. Assign roles conservatively at first.

## What “done” looks like

You are ready to use the workspace when:

- the project exists
- the board reflects the real workflow
- at least a few tasks are assigned
- due dates show up in planning views
- the team can comment and update work without confusion
